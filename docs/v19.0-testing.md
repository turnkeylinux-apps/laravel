# Laravel 19.0 testing

## Scope and dependency decision

Debian 13 Trixie does not package the Laravel application framework. The
appliance installs the official Laravel 13 application skeleton tag v13.10.0
at commit `9863f0544931b7e3062001a28e37f4fcf795ce5c`. The skeleton supplies
supported dependency constraints rather than a lock file, so Debian's Composer
resolves the production graph during the build and retains the generated lock
file in the appliance. Laravel 13 is the current upstream major line and
receives security fixes through Q1 2028.

PHP 8.4, MariaDB 11.8, Apache, Composer and PHP extensions come from signed
Debian Trixie repositories. Composer is the supported in-appliance updater for
framework dependencies within the Laravel 13 constraint. New framework major
versions follow Laravel's documented upgrade process.

## Deferred issues

- Docker runtime validation does not exercise the installer, appliance
  kernel, bootloader or physical hardware. Laravel adds no appliance-specific
  behavior at those boundaries, so the validated Core 19 baseline supplies
  inherited evidence.
- The appliance provides a one-shot queue worker command rather than choosing
  a production worker topology for the developer. Applications can select
  their own worker count and process supervision after deployment.
